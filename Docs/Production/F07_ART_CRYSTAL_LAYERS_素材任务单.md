# F07-ART-CRYSTAL-LAYERS：Blender水晶舞台拆分交接

对应程序任务：P19-CRYSTAL-MOTION。用户授权修第2项：外环、内部水晶、漂浮碎片、群星都运动，法阵进入水晶画面连贯。当前交付为素材需求，尚未实施或验收水晶新效果。

## 用户最新调整：以3D拆分模型为正式交付

用户确认这个舞台以前为3D，采用“美术在Blender拆好，程序在Unity编辑动画”。本节覆盖下文旧PNG方案：六张PNG不再是必需交付，旧规格仅保留作历史备选。优先使用现有 `ArtSource/Scenes/SummonStage/v004_click/A05_ClickCrystal_v004.blend`，另存新版，不覆盖旧母版。已有交接说明母版含12个晶体碎片；本轮需美术实际检查它们是否能作为独立网格导出，不因旧记录就宣称Unity已可用。

### 必需模型拆分

建议根节点 `CrystalStage`，其下保留独立物体/网格与明确名称：

| 节点/组 | 拆分要求 | Unity负责 |
|---|---|---|
| RingOuter | 外侧完整巨环，可按同转速的轨道合并，不与内环合并 | 独立旋转、镜头推进 |
| RingInner | 内侧完整环，与外环分开 | 反向/不同速度旋转 |
| RingFloor | 水晶下方法阵，独立网格 | 水平旋转，与前奏衔接 |
| CrystalBody | 中央水晶；其不同切面保留真实几何 | 浮动、轻微自转/倾斜、连击震动 |
| FloatingIce_* | 外围冰蓝漂浮晶体，至少两种轮廓，各自独立网格 | 轨道、公转/自转、上下起伏 |
| FloatingGold_* | 外围金色棱块，各自独立网格 | 不同轨道与起伏 |

中央水晶如果由12块晶壳组成，保留 `CrystalBody/Shard_00…` 等子节点；每片网格和原本完整状态位置可单独访问。保留原裂纹/碎裂能力与参考，不要求本轮制作第3项光束或第4项爆裂新动画，也不直接用离线固定三次点击时间轴驱动游戏。

### 交付文件

- `F07_CrystalStage_v001.fbx`：完整舞台，包含上述独立网格，保留节点层级和材质槽。导出可直接导入Unity的静态模型；本批动画由Unity制作，不要求烘焙循环动画。
- `Source/F07_CrystalStage_v001.blend`：可编辑新版母版，保留源几何、材质和相机/灯光参考。FBX为运行导入入口，不依赖Unity直接转换blend或本机安装Blender。
- `Textures/`：模型实际需要的Base Color、Normal、Metallic/Roughness、Emission等贴图；纯色材质可只交参数，不为没有使用的通道凑图。说明色彩空间/通道布局。程序映射到现有URP材质，不能假定Blender节点材质导入后完全等效。
- `Review/`：Blender完整舞台预览和节点层级截图；注明相机位置、朝向、焦距/正交尺度、灯光颜色与强度作为对照。相机和灯光不必强行变成FBX运行节点。
- `manifest.md`：模型/贴图路径、节点说明、尺寸/单位、导出轴向与缩放、材质槽对应、源制作方式、SHA256、实际检查结果及缺项。

### 模型要求

环的旋转中心放在环几何中心；水晶根中心和各碎片局部旋转中心设置合理。父级统一管理尺度，避免负缩放和非均匀缩放造成旋转变形。应用需要的旋转/缩放时保持完整舞台外观；manifest明确单位和轴向，并做一次回导检查。晶体/环面法线、UV与材质槽有效，完整圆环不要只保留旧相机可见部分。没有相机、灯光、用户名、字幕或UI烘焙进模型贴图。

背景不需要建满屏星点网格：沿用已验收的星空/星云纹理与程序星点。已有外围晶块优先直接拆出；缺少独立几何时按原风格补齐，而不是从合成背景截取。交付仍放 `ArtSource/Effects/F07/CrystalLayers/`，包名 `F07_CrystalLayers_v001.zip`。

### Unity集成范围

程序先验证FBX层级、材质与实际渲染，再把舞台接入Main的水晶阶段，以连续时间控制环、晶体、碎片运动，并让镜头/环构图从前奏自然接入。3D显示与现有uGUI界面合成，保留签约、唯一Draw、点击蓄能、跳过清理和逐张确认；不扩框架。已验收角色揭晓背景和P18效果继续保留。第3项投射光束、第4项碎裂白光单独验收，不把导入3D模型等同于两项已完成。

## 导出与对齐要求

1. 成品PNG是真实透明RGBA，无深色底板、棋盘格、文字、Logo、角色和UI。边缘留8%透明安全区，包括柔光不能被截断。
2. 三环画布中心均为(0.5,0.5)，保持完整圆形；建议各图主圆最外径统一约画布84%，舞台内的大小关系由程序设置。不要在2048画布里把内环画成很小一圈，造成混用尺寸难调。
3. 碎片画布中心为元素旋转中心，长轴竖直；透明边距保留，不逐张自动裁边。方向/轻微翻转/角度由程序处理。
4. 环保留适度金色材质和细刻度，辉光较轻；程序叠加光效，不交强白色泛光糊死细节的版本。片图不要把多个不同碎片拼成无法分开的整张。
5. 为转动后的显露区域补齐完整轮廓，不只抠当前1280×720截图中可见的部分；无法取得原几何时按同风格重建完整环，记录来源。

## 程序负责与验收

P19负责：内外环不同方向/速度连续转动；底环缓慢转动与透视；中央水晶轻微浮动/倾斜、点击震动；碎片沿不同椭圆轨道运动并叠加独立上下起伏；背景星点慢漂移/闪烁。运动使用连续时间，不因一次点击重置轨道。

法阵进入水晶采用同轴环形构图，原法阵逐渐拉近/立起，新环与水晶渐入；避免前奏结束立即关旧画面再开新背景。水晶动画承接前奏动势，进入蓄能等待后继续运动。2D/2.5D先跑通，不要求本批完整3D场景或视频。

实际Main验证自然播放进入水晶、慢点/高频/停手、转场期间和蓄能期间跳过、三窗口画面边缘。签约与补签、唯一Draw、蓄能保持、角色逐张确认仍沿用现有行为。已验收角色阶段星云与P18效果保留。本批不提前扩第3项投射光束和第4项碎裂收尾，也不把它们混入本次素材验收。
