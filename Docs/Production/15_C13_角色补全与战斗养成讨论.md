# C13：角色补全与战斗养成讨论

日期：2026-10-11。用户明确水晶互动当前版本已验收，下一步讨论角色人设/立绘补全及获取抽卡资源、简易战斗、角色养成。随后选择：**三人卡牌，自动普攻与小技能，点击角色头像释放有冷却的大招；主要玩法是编队与养成。**

本文件是讨论稿。战斗形式按用户回复记录；具体角色设定、技能、奖励、等级和施工顺序为总指挥建议，尚未派工。本轮不改Unity、不生成角色、不重跑已验收水晶版本。

**同日后续补充：** 用户进一步明确肉盾/战士/射手/法师/辅助分类，并要求先给冰法师命名再设计其余人设。最新人物设定以 [16_C14_角色人设与职责.md](16_C14_角色人设与职责.md) 为准：冰法师设计名“伊瑟琳·霜庭”，补生命/攻击/防御，2肉盾/2战士/2射手/3法师/3辅助。下文按该设计更新，资源/成长/奖励仍是讨论参数；游戏当前显示名和战斗配置尚未接入。

**C14-R1修订：** 元素只用冰/火/风/雷/光/暗六类；星/月/灯火/海潮等保留为视觉主题，生命/攻击/防御不变。人设改为宅系二次元的反差性格与亲近感，服设使用轻度露肤、丝袜、局部镂空，具体逐人设计以16为准，当前未生成新增衣物细节。

- 冰法师有实际透明立绘；另五名有职业样稿，六名仍缺正式角色图。按冰法师规格补全的生产范围是**其余11名**，其中五名优先保留已选设计后精修，六名先做人设。
- 后续P06—P32已对水晶/星云/契约/角色/结算持续迭代；最新P32交接记录当前头像小卡、NEW、SSR/UR外围光已获用户验收。旧F10素材任务单不覆盖最新已验收结算布局。

## 3. 美术生产按批验，不一次生成11张后才检查

建议顺序：

1. 按16的12人初稿确认五类职责与画面轮廓，保留已选职业样稿的可用设计。
2. 做赛蕾娜正式透明立绘和米洛护卫样张，与伊瑟琳一起放实际登场、头像、战斗排布中验证。
3. 做芙蕾娅正式人物层、星澜、艾露薇；随后补余下六人。整批结束得到12名角色，不新增卡池。

每名交付统一1024×1536、2:3的实际高质量母版、真实RGBA人物层、同角色头像/缩略图、可保留的独立背景/源稿。武器、头发、脚部和衣摆留安全边距；不得用单纯放大768稿冒称补齐细节。脸部焦点/头像裁切位置逐角色记录，供现有近景缩回与结算头像使用。

普通角色也有完整、好看的基础立绘；高级角色增加姿态、材质和演出层次。全部保持既有成人角色方向。文字、稀有度框、徽记、NEW和特效继续由Unity分层，人物PNG不带卡框、名字或棋盘格。

战斗首版复用同一透明立绘/头像，技能通过短位移、投射/闪光、护盾/治疗特效表达。无需先做另一套战斗角色、跑步攻击姿势、3D角色或骨骼动画。生成链路执行时再核对本地ComfyUI实际在线状态、模型和抠图效果，旧生成记录不证明当前运行能力。

## 4. 战斗：三人编队，自动小技能，手动大招

建议总人数三名，可选1前2后或2前1后，职业决定默认前后排。玩家从已拥有角色选三人，先验证配队而不开放复杂自由站位；普攻/小技能自动执行，手动操作集中在三个头像的大招。首次样例先做一张静态战场、一组敌人、约30—60秒的一场战斗，实际节奏再调整。

| 定位 | 自动行为 | 点击头像释放的大招示例 | 玩家关注 |
|---|---|---|---|
| 米洛·肉盾 | 普攻，周期自回血 | 自身护盾与短嘲讽 | 敌人点名时保护后排 |
| 伊瑟琳·法师 | 普攻冰弹，周期冰系小技能 | 范围冰爆、短冻结 | 输出与敌人危险动作时机 |
| 赛蕾娜·治疗辅助 | 普攻，周期治疗最低生命比例队友 | 明显的团队恢复 | 群攻后恢复，避免满血时浪费 |

每人先只要生命、攻击、防御、职业/默认排位、六类元素之一、物理/魔法伤害类型、等级、自动小技能与一个大招。首版统一防御，不另加物防/魔防成长或元素克制表；星/月/灯火/水等不能另设元素。角色攻击间隔/技能冷却作为配置，不另加速度养成属性。建议大招开局约3秒后可用，随后12—18秒冷却，均是待试玩的起点；不用另外做能量、怒气或手选目标。

普通攻击集中攻击当前敌人；敌人普攻优先打前排，前排倒下后顺次选存活角色。嘲讽将可重定向的敌方单体攻击转给肉盾；群体攻击仍打全队。敌人可有清楚预兆的群体攻击及后排点名攻击，让护盾、治疗、嘲讽有用途，先用其中一种危险动作测首队。治疗自动选择合适队友，攻击大招自动选择当前敌人。首版规则直接清楚，不引入元素克制表、连携树或复杂仇恨。

头像显示血量、冷却遮罩/秒数和可释放亮边。角色/敌人行动、伤害、护盾和治疗有可读反馈；大招使用短特写/特效强化角色身份，不重复召唤水晶仪式。胜负结算给奖励，允许立即再战或回到培养/召唤。

实际游戏性来自：坦克/输出/支援的搭配、站位、培养对象，以及护盾/治疗/爆发大招释放时机。先用三种队伍测是否有区别：护卫+输出+治疗、双输出+治疗、三输出。

## 5. 最小资源与养成循环

**编队 → 战斗 → 获得抽卡资源＋训练经验 → 抽到新角色/重复补经验 → 选择培养对象 → 调整编队 → 挑战下一关。**

建议先做三关，复用一个战场与少量敌人，通过数量、血量/攻击和一个危险动作产生递进，不先生产完整章节。第一版成长上限建议Lv10，使用一种通用训练经验升级，提升生命/攻击/防御；暂不叠加装备、突破材料、技能树或多个培养货币。

| 收获 | 首版建议 | 目的 |
|---|---|---|
| 新手资源 | 沿用现有30抽；提供一支能出战的基础队，具体赠送名单再定 | 不依赖随机抽到坦克/治疗才能开局 |
| 战斗胜利 | 约2份抽卡资源＋通用训练经验 | 大约5场可进行十连；数值以短试玩调参 |
| 首次通关 | 额外抽卡资源，解锁下一关 | 给短期目标和第一次推进的奖励 |
| 重复角色 | 保留当前持有次数，并额外赠少量通用训练经验 | 重复有轻度价值，不要求攒同名卡才能成长 |
| 培养 | 玩家选择角色消耗经验升一级 | 立刻可见的队伍成长和下一关目标 |

奖励是讨论参数，不是已冻结经济。正式循环需要把当前玩家页无限“+10”改为战斗资源入口；开发补充保留Editor验证。抽卡演出试玩版是否继续保留为独立入口后续再定，不把两种入口混成一个正式资源循环。

战斗失败保留已获得角色/等级，可回培养、换队、重试；不为失败设置资源罚款。为保证资源用尽仍能继续玩，基础挑战可重复进入，不消耗抽卡资源。奖励只在一场结束时结算一次，不扩防御性事务框架。

有了成长，建议同一小版本补最小本地保存：资源、收藏次数、角色等级/训练经验、三人编队、关卡进度和昵称。延用现有内存结构，按角色ID保存；让这条养成循环能跨次游玩。不是先启动旧完整存档工程或故障测试体系。

## 6. 建议施工节奏（尚未派工）

| 小批 | 交付目标 | 验收判断 |
|---|---|---|
| 人设与首队美术 | 12人设定，先冰法师/光牧师/米洛三人可用 | 同风格且职责/剪影不同，登场、头像、战斗都能消费 |
| 三人战斗样例 | 编队、自动普攻/小技能、三个有CD大招、胜负结算 | 角色定位可见，点头像有用，约一分钟内完成 |
| 资源/成长闭环 | 奖励入账、升级改变战斗、召唤加入可选队伍、最小保存 | 玩一场→升级/抽卡→换队→再打一场；重开保持进度 |
| 其余角色与关卡 | 补齐12名、三关、微调奖励和冷却 | 十分钟试玩能看见新队伍/新角色/成长目标 |

总指挥建议尽快把首队与战斗样例接起来，不等11名美术全部完成再验证玩法。程序、UI、美术后续按一次一个任务ID施工，共享角色身份/状态接口由程序产出并交接；总指挥仍只计划和验收。

后续任务候选为角色设定/首队素材、战斗样例、编队战斗UI、资源成长和最小保存；待本讨论收口再给允许写入范围、接口和可复制提示词，不自动启动。

涉及Unity概念：ScriptableObject角色配置、按角色ID关联战斗与收藏、自动行为计时与冷却、头像按钮/血条、短技能特效、战斗结束结算、本地保存。调参入口：基础生命/攻击/防御、普攻/小技能间隔、大招冷却/效果、敌人危险动作、奖励量、每级经验和属性成长。
