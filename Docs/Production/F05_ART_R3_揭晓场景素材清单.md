## 动态怎么拆

星空底图、两层星云、恒星、流星必须独立交付，不能全部合成一张静态背景。星云需要可循环的图，不需要美术先做视频；恒星闪烁和流星轨迹由程序做，避免循环影片固定重复同一段。

NEW 边框交付白色透明遮罩，程序实现青→紫→粉→金的流动渐变，另用四芒亮点沿边运动；不要把动态渐变烘成一张纹理。美术可额外交一张彩色静态示意，供核对设计，但不能替代白色遮罩。

稀有度字图需要统一画布、文字基线和安全边距，短字不拉宽。R/SR/SSR/UR 图片内只包含对应英文字母，禁止额外星数、职业名、中文名或徽章。角色中文名称继续由 UI 动态排版。

## 交付与验收

- 原图放 `ArtSource/Effects/F05/RevealR3/`，按上表文件名交付；源文件如有 PSD/分层工程一并保留，PNG 必须能直接使用。不要写入 Unity Library 或覆盖旧 v002。
- 额外交一张 `reveal_layout_preview_v003.png`（1920×1080 或以上）展示整体拼合效果：现有冰法师、简化雪花、深邃星云星空、金色 SSR、彩色 NEW 边框。右侧约 20% 保持留白，左侧文字不被星云干扰。
- 透明图片没有黑/白底、棋盘格、明显光晕裁切；检查四周留白，边缘不出白边。星云重点检查左右循环接缝。
- 四档稀有度在实际 UI 缩到约 120—200 像素宽时仍清晰，NEW 缩到约 80—140 像素宽时仍可读。渐变不能吞掉字形。
- 不要求重新生成角色、十二角色专属背景、卡池界面、额外产物图标、按钮或语音。本轮先完成冰法师揭晓的这套素材。
- 附 `manifest.md` 列明每张尺寸、透明背景、生成工具/模型、提示词及版本。Unity 导入、.meta、实际动画与 Main 验证由程序后续完成。

程序接入说明：现有界面尚只有单个 SSR Sprite 引用。后续将扩展表现配置支持四档标识与分层背景，不改变角色数据、概率、Draw 次数或收藏逻辑。当前无需美术适配旧的繁复徽章尺寸。
