# 最快可玩原型：第一步 F01

用户于 2026-10-07 调整优先级：最快做出可玩版本，不先关注完整规则、防御性编程和可靠性工程。

## 第一步的目标

打开 Unity，按 Play，能执行：单抽/十连 → 简短揭晓 → 结果 → 卡牌详情 → 返回再抽。可以查看本轮收藏，资源用完点击免费补充。

第一步搭四个组成部分：一个主场景、一个内存抽卡模型、一个简单揭晓控制、可切换的页面。框架直接带可玩的闭环，不先建设通用架构。

## 实施范围

- 12 个角色稳定 ID，先用名字和稀有度色块占位。
- 简单基础随机权重 70/24/5/1；首轮不做保底、赠礼、玄学和共鸣。
- 初始 30 抽、免费补充 10 抽；收藏次数仅存在本次运行内存，退出 Play 重置。
- 召唤、揭晓、结果、详情、收藏页面；现实桌面后移。
- SSR/UR 有独立预览入口，便于先体验高级颜色与节奏。
- 不增加框架依赖、不做存档事务、不写规则测试套件。
- 首轮中文 UI 可用 uGUI 内置 Text 与运行时 Windows 字体；正式视觉确定后再整理 TMP 字体资产。

## 最小代码分工

| 文件 | 用途 |
|---|---|
| `Assets/_Game/Scripts/Core/PrototypeGacha.cs` | 角色表、基础随机、资源、内存收藏 |
| `Assets/_Game/Scripts/UI/PrototypeGame.cs` | 页面、占位卡面、按钮绑定和简短揭晓 |
| `Assets/_Game/Editor/PrototypeSetup.cs` | 创建 Main 场景、打开入口、最短流程验证 |

暂时只用默认 Unity 程序集，不先拆 asmdef。美术通过 `PrototypeGame` 的角色图片映射字段替换占位图，名称由小角色表修改。

## 运行方式

导入脚本后，Unity Editor 将创建 `Assets/_Game/Scenes/Main.unity`。菜单 `Tools/这次一定出/打开可玩原型` 可打开主场景，点击 Play 开始。现有示例场景按 Play 也会自动启动原型界面，便于立即体验。

菜单 `Tools/这次一定出/创建原型主场景` 可重建缺失的入口；已存在的主场景不覆盖。业务测试仅运行最短按钮流程，不模拟十万次概率或注入文件故障。

## 第一轮完成标准

1. Unity 编译通过。
2. 点击单抽和十连能显示相应数量的结果，资源相应减少。
3. 结果可打开详情，详情能返回，收藏显示本轮收录。
4. 揭晓可跳过，返回后能继续抽，资源可免费补充。

验证证据与当前限制在 `F01_交接.md` 记录；完成代码但未运行时仍标待验收。

## 下一步

完成 F01 后，接入一张用户选定风格的 SSR 实图，集中做“预兆 → 揭晓 → 停留欣赏”的手感，再验证 UR 差异。优先回答“这次出货好不好看、想不想再抽”，规则与工程化按体验需要逐项补。

## 学习点与调参

- Canvas/RectTransform：页面放置与分辨率缩放。
- Button 事件：点击触发游戏动作。
- Coroutine：控制短揭晓时序。
- 普通 C# 对象：本轮资源、结果和收藏。
- Inspector 中的图片映射：按角色 ID 换立绘；代码中修改揭晓时长和主题颜色。
