## 3. 抽卡计算契约

### 3.1 计算顺序

一次请求只允许 1 或 10 抽，先锁定请求并校验资源。对状态副本逐格执行：决定赠礼/保底/正常路径 → 稀有度 → 角色权重 → 版本 → NEW 标识 → 更新副本的资源、保底、收藏、事件。整批成功后一次提交完整存档，再发布结果和播放演出。

十连中每一格都使用前一格更新后的副本。NEW 也按格计算：同一角色在同批第二次出现不能再次显示角色 NEW。共鸣首次获得时可同时为角色 NEW 与版本 NEW。

正常路径先抽稀有度（R/SR/SSR/UR = 70/24/5/1），同稀有度角色等权重。角色支持共鸣时才独立判版本，基础条件概率 5%。未支持者不判共鸣。

### 3.2 保底状态

字段 `srDryCount/ssrDryCount/urDryCount` 表示过去连续未满足 SR+/SSR+/UR 的抽数。正常状态范围分别为 0—9、0—29、0—99。

当前格计算前检查：`urDryCount>=99` → UR；否则 `ssrDryCount>=29` → SSR:UR = 5:1；否则 `srDryCount>=9` → SR:SSR:UR = 24:5:1；否则基础权重。强制保底不是“先抽一次，再补发一张”。

当前格结束后：满足对应门槛计数置 0，否则加 1。UR 重置全部，SSR 重置 SR/SSR，SR 重置 SR。UI 显示 `30-ssrDryCount` 与 `100-urDryCount` 抽内必得对应等级，事件不影响这些数值。

### 3.3 两条玄学

| 事件 | 触发判定 | 效果 | 消耗 |
|---|---|---|---|
| 主页倾向 | 当前结果等级是 SSR 且不是赠礼；含保底 SSR | 目标 SSR:另一 SSR = 3:1；SSR 条件概率 75% | 做完这次 SSR 角色选择即消耗，抽到另一名也消耗 |
| 生日祝福 | 不是赠礼且角色是配置的生日对象；含保底结果 | 该角色的共鸣条件概率 25% | 做完这次版本判定即消耗，未出共鸣也消耗 |

主页倾向抽到 UR/R/SR 不消耗；生日未抽到目标不消耗。重复激活只保留一份，主页可换目标。两者独立，可在同一格同时生效。此处“自然”排除赠礼，包含硬保底。

SSR001 作为生日目标是建议，必须校验支持共鸣。事件入口可重复使用，无现实日期锁定和等待时间。

### 3.4 新手赠礼与冲突

按原案：首次十连第十格固定普通 SSR，SSR001/SSR002 等概率，不消耗两条玄学；计抽数，重置 SR/SSR，UR 未出计数加 1。首次单抽不会领取赠礼。赠礼必须有可见标识。

原案遗漏的冲突：首次十连开始时 `urDryCount=90`，前九格未出 UR，则第十格同时要求 UR 硬保底和固定普通 SSR。两者不能在同一格成立。

**策划补充建议（待 M2 前冻结）：UR 硬保底优先；只有发生此冲突时，SSR 赠礼改为该十连第九格，第十格兑现 UR。** 从第九格之前的状态重新顺序计算第九/十格，赠礼仍不消耗玄学，NEW/收藏/保底全部按最终顺序重算；只提交最终十张结果，不多扣费、不多发一张。

程序实现须将这个补充当作显式策略并用可恢复的随机源/计算快照处理，不能临时篡改已经提交的结果。该建议保留同批赠礼和 100 抽 UR，代价是极少数情况下赠礼不在第十格。原策划案暂未修改；总指挥冻结后同步 UI 说明。M1 不包含赠礼，因此不受此待定项影响。

### 3.5 演出计划

`PullResult` 的稀有度/版本是权威结果。SSR/UR 有 20% 概率采用一次升格，仅改变展示路径。独立的展示随机源不影响抽卡随机序列；展示计划和抽卡结果一起保存，重播/重进不能改变卡牌或升格选择。

新手赠礼最终是 SSR，可用高级演出；标识须保留。调试强制卡和重播均进入测试通道，不修改正式保底/收藏/赠礼领取状态。

## 4. 数据模型与接口草案

以下是最小共享语义，不是已经存在的类。程序 P01 产出真实 C# 后，总指挥将字段/签名冻结，UI 用适配器接入。

| 模型 | 必需字段 |
|---|---|
| CharacterDefinition（SO） | characterId、displayName、title、rarity、supportsResonance、固定展示属性、素材与演出引用 |
| PoolDefinition / GachaRules（SO） | poolId、角色集合、基础权重、3 档硬保底、共鸣率、事件参数、rulesVersion |
| PlayerState（运行态） | schemaVersion、revision、currency、totalPulls、保底 3 计数、starterGiftClaimed、collectionEntries、eventState、displayCard、pendingBatch、settings |
| CollectionEntry | characterId、normalCount、resonantCount、角色首次获得 UTC、各版首次获得 UTC |
| EventState | homeTargetCharacterId、homeUsesRemaining(0/1)、birthdayTargetCharacterId、birthdayUsesRemaining(0/1)、群聊/公告引入标记 |
| PullResult | index、characterId、rarity、variant、isStarterGift、isNewCharacter、isNewVariant、promotionPlan |
| SummonBatch | transactionId、rulesVersion、count、orderedResults、committedAtUtc、presentationAcknowledged |
| CardViewData | 角色显示信息、素材引用、当前版本、拥有数量、首次获得时间、欣赏解锁状态 |

存档保存 ID 与基本字段，不直接保存 Sprite、Material、ScriptableObject 或场景引用。`JsonUtility` 采用可序列化类和列表字段；字典不直接进入存档 DTO。程序可用运行时字典加速，读写时转换列表。[Unity JSON Serialization 文档](https://docs.unity3d.com/2022.3/Documentation/Manual/JSONSerialization.html)

建议对 UI 暴露的门面（具体 C# 错误类型由 P01 定义）：

```text

TrySummon(count)                               成功返回已提交 SummonBatch；失败返回错误
TryRefillCurrency()                            免费 +10；保存成功后发布状态
```

演出接口建议：`Play(SummonBatch)`、`AccelerateCurrentPhase()`、`RevealNext()`、`SkipToSummary()`、`ReplayForDebug(result)`，以及 `CardRevealed/PlaybackCompleted` 通知。演出脚本不能调用抽卡计算或直接保存收藏。

UI 通过一个 GameFacade/门面引用请求动作，显示更新后的只读数据。按钮可先绑定同形 mock；mock 与正式实现使用同一接口，不能把模拟随机代码混入正式页面。

## 5. 事务与恢复

1. 只允许一个进行中的召唤请求；保存阶段与演出阶段的重复召唤均不可入队扣费。按钮禁用和服务端重入保护都要有。
2. 计算仅修改状态副本；保存内容含整批结果、扣费后的资源、收藏、事件和保底。
3. 临时文件写入后在相同目录替换正式文件，并保留备份；首次保存使用创建路径。具体替换实现必须在目标 Windows/.NET 环境实测。
4. 确认提交成功才替换内存状态并发通知。确定未提交的失败不扣费、不发卡、不消耗事件；给出可重试入口。
5. 若 I/O 异常发生在可能已替换成功的时点，重读正式文件核对 transactionId/revision；已提交则展示原批次，无法判断则进入存档恢复流程，不能自动发起第二次抽卡。
6. 演出中关闭游戏，重启加载已提交收藏；pendingBatch 直接进入上次结果总览。再次跳过/打开不重复发卡。
7. 总览出现后记录展示已确认；若该保存失败，允许再次显示相同总览并重试，不重复扣费。确认状态完成后才开启下一次召唤。
8. 正式存档损坏先尝试备份；未知未来 schemaVersion 给出恢复提示，不自动清空。重置测试存档不得指向正式存档。

UTC 时间入库，界面转换为本地显示。UI 隐藏/显示、图鉴筛选、版本预览等不应造成抽卡状态变化。

## 6. 收藏规则

- 普通/共鸣次数分别记录；共鸣获得不增加普通版次数。
- 任一版本可解锁角色基础立绘欣赏；版本切换只允许已拥有版本，未拥有版显示未解锁状态。
- 可以有“普通图像可欣赏，但普通版拥有数=0”的情况，UI 不把欣赏权限误当拥有数量。
- 桌面展示必须选择已拥有版本；失去有效引用时回退到安全默认，不生成一张卡。
- 固定强度属性只展示，不参与战斗或随机洗练。

## 7. 素材契约

| 资源 | 交付格式 | 要求 |
|---|---|---|
| 基础完整卡面 | PNG，1024×1536，2:3 | 无文字/边框/水印，保留无损母版 |
| 人物层 | PNG RGBA，同画布 1024×1536 | 真实 alpha；不是棋盘格或白底伪透明 |
| 背景层 | PNG，同画布 1024×1536 | 分层时补齐人物移开后的空洞 |
| 前景层 | PNG RGBA，同画布；可选 | 不遮挡面部，层数克制 |
| 缩略图 | PNG，256×384 | 从正式稿派生，不另生成改变身份 |
| 通用背景 | PNG，1920×1080 | 留出按钮和信息安全区，无 UI 文字 |
| 粒子纹理 | PNG RGBA，256/512 方图 | 简单符号、环纹或光斑，不带烘焙整屏特效 |
| UI 基础框/按钮 | Unity Image/9-slice/SVG 源设计 | 由 UI 实现，保证可伸缩可点击 |

先保留母版质量；低显存可低分辨率构图后放大/修复，但交付像素尺寸不等于已经具备相应细节质量。需要检查最终图。

构图起点：人物约占画面高度 75%—85%，脸部重点位于上半部中心附近；四边约 5% 留白，底部约 15% 避免放关键脸/手/道具。安全区随 U01 实际卡面校准后冻结，不能为了留白把所有姿势强制成同一个模板。

角色层、背景层、前景层保持同一画布原点与尺寸，不各自紧裁。SSR/UR 首批必须验证分层视差；其他角色允许先完整卡面。完整图不可直接冒充可运动分层。

文件示例：`SSR001_card_base_v001.png`、`SSR001_character_v001.png`、`SSR001_background_v001.png`、`SSR001_thumb_v001.png`。资产 ID 使用清单中的稳定值；版本升级保留母版记录，Unity 引用更新由对应资产负责人处理。

每个正式图对应 metadata：提示词、实际模型/LoRA/VAE 和校验值、seed、尺寸、采样器/调度器/steps/CFG（如适用）、工作流路径、ComfyUI/节点版本、修复与抠图过程、最终哈希、缺陷与验收结论。不适用参数写不适用，不猜测。

## 8. UI 与演出契约

- 参考尺寸 1920×1080，CanvasScaler 为 Scale With Screen Size；1280×720、16:10 窗口实测。
- 全工程一个受控 EventSystem；按钮不用透明全屏层遮挡。装饰 Image 关闭 Raycast Target。
- 六页：Desktop、Summon、Reveal、Summary、Collection、Detail；概率/设置使用轻量弹层，不扩成多步教程。
- 启动两次点击开始首次抽卡：点击桌面游戏入口，点击召唤按钮。默认 30 抽，不要求先领取消息。
- 抽卡页固定单抽/十连/资源/SSR及UR保底位置。保存中展示忙碌状态，失败恢复可操作状态。
- 十连支持加速当前阶段、揭晓下一张、跳过剩余；完成后进入总览，跳过保留角色 NEW、版本 NEW、共鸣、赠礼标识。
- 概率页读取实际配置；显示基础权重、硬保底、共鸣条件概率、事件条件和赠礼例外，不能写“每抽有 5% 共鸣”。
- 共鸣版在图鉴缩略图、详情和桌面展示都有持续边框/标识；默认不另换角色图。
- 详情支持隐藏 UI、返回、已拥有版本切换、收录时间/次数、设置展示卡、视差开关；隐藏 UI 后保留可发现的恢复入口。
- R 蓝、SR 紫、SSR 金、UR 黑金/主题色是建议；同时使用文字、符号和不同运动，不能只凭颜色区分。
- 第一版基准时长：R 1—2 秒、SR 2—3 秒、SSR 4—6 秒、UR 首次 7—9 秒、共鸣附加 1—2 秒。非首 UR 和普通重复卡可缩短，但用户可跳过。
- 淡入、剪影、震动、材质、声音是演出层；不能通过“升格动画”再次判稀有度。

## 9. 必测用例

| 编号 | 条件 | 必须成立 |
|---|---|---|
| T01 | srDryCount=8，再连续 R | 下一格达到 9 后，第十次未出序列必为 SR+；边界无偏一 |
| T02 | ssrDryCount=29 / urDryCount=99 | 下一格分别只能 SSR+/UR |
| T03 | 三计数同时临界 | 最高 UR 优先，全部计数归零 |
| T04 | 相同状态、相同随机序列，10 次单抽对比一次十连 | 除显式赠礼规则外结果/保底/事件一致；该用例关闭赠礼或设已领取 |
| T05 | 主页目标激活后抽到非目标 SSR | 按 3:1 选择并消耗；UR/R/SR 不消耗 |
| T06 | 生日目标出现但普通版 | 使用 25% 判定且消耗；目标不出现不消耗 |
| T07 | 正常新手第十格赠礼 | 普通 SSR、两名等概率、事件不消耗、UR未出数+1 |
| T08 | 赠礼第十格与 UR100 冲突 | 按冻结策略仍恰好十张、兑现 UR、SSR赠礼无事件消费、最终状态顺序一致 |
| T09 | 连续点按钮、保存未结束、动画未结束 | 同一请求只提交一次，额外请求被拒绝，无双扣 |
| T10 | 保存写入失败 / 替换结果不确定 | 确定失败状态无变化；不确定时核对已存 transactionId，不再次抽取 |
| T11 | 保存成功后关闭、跳过、重播 | 恢复同一结果、收藏不二次累加、升格计划不变 |
| T12 | 同批同角色首次普通后共鸣 | 第二格不再角色 NEW，但首次共鸣可版本 NEW；次数分开 |
| T13 | 初次只有共鸣 | 普通次数为 0，基础立绘可欣赏，普通版不能冒充已拥有 |
| T14 | 免费补充、重进 | +10 持久化，没有广告、等待或额外系统 |

概率验证另外报告：无保底/赠礼/事件的基础分布、归一化保底分布、SSR角色3:1、目标共鸣25%。建议基础模拟不少于 100,000 次，固定 seed、输出样本数与偏差/置信区间；UR 稀有事件不要用几十次抽卡判定正确性。
