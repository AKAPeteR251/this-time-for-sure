# 施工规划

**当前执行范围已调整：用户要求最快做出可玩原型。先执行 [F01 最快可玩原型](07_最快可玩原型.md)，用内存数据和占位 UI 跑通抽卡闭环。下面的完整规则、存档可靠性和验收体系属于后续目标，不是第一步前置条件。**

## 1. 判断与项目现状

策划案已明确核心卖点：出货前的期待、角色揭晓、共鸣的第二次惊喜、卡牌欣赏。V0.1 应围绕一次完整召唤安排工程，而不是先搭复杂的生活模拟框架。

本地实际检查结果：

| 项目 | 现状 | 施工决策 |
|---|---|---|
| 工程位置 | 工作区下的 `这次一定出/` | 所有游戏文件写入内层工程 |
| Unity | 2022.3.53f1c1 | 保持版本，先验证本机 Editor 可用 |
| 渲染 | URP 14.0.11，3D 示例模板 | 沿用管线，制作以平面卡面为主的体验 |
| UI | 已声明 uGUI 1.0.0、TMP 3.0.7 | 使用现有 UI 包 |
| 动画与测试 | Timeline 1.7.6、Test Framework 1.1.33 | 基础演出状态机；必要时 Timeline；核心规则测试 |
| 输入 | activeInputHandler=0，旧输入体系 | 保持现有体系，桌面鼠标和 EventSystem 优先 |
| 场景与业务 | SampleScene；模板说明脚本；无游戏业务 | 新建 `_Game` 内容，不依赖模板已具备玩法 |
| 默认尺寸 | 1024×768 | 后续改为 16:9 窗口，按 1920×1080 设计 UI |
| 版本管理 | 工作区和内层工程未发现 `.git`，git status 失败 | M0 建议建立本地 Git 与 Unity 忽略规则，备份原模板 |
| ComfyUI | 未确认地址、模型、工作流、显存 | 模型无关地先定义交付格式，A00 再核对环境 |

这次没有运行 Unity、构建游戏、连接 ComfyUI 或生成图像；项目现状是文件检查结论。

## 2. 第一版完成的具体样子

进入桌面 → 点击游戏入口 → 单抽或十连 → 预兆/揭晓/共鸣 → 结果总览 → 详情欣赏 → 设为桌面展示 → 再次召唤。首次启动赠送 30 抽；资源耗尽可立即免费补充 10 抽。

最终包含 12 个角色、一个常驻池、4 个共鸣支持角色、单抽/十连/三档硬保底、本地存档、6 个页面、两位群友和三项轻量事件内容。两条玄学可同时生效，且各自准确显示影响对象和剩余一次。

不纳入本版：战斗、装备、随机强度、生活属性、交易、排行榜、真实付费、额外卡池、角色配音、完整 Live2D。装饰性功能不能阻塞核心循环。

## 3. 推荐技术路线

### 3.1 图像与渲染

采用“2:3 分层角色图 + 可交互 UI + 局部特效”。UR 优先人物/背景分层与轻微视差；SSR 同样优先分层；R/SR 可先用完整卡面。保留 URP 3D 模板，不为卡片玩法额外制作可探索 3D 房间。

界面使用 uGUI 与 TMP。卡牌构成背景、人物、少量前景、边框、文本、共鸣材质；边框、名称、NEW、按钮由 Unity 组件绘制。ComfyUI 不承担文字和可点击布局。

召唤演出先用 C# 阶段控制和简单过渡；UR 独有运动确有需要时再上 Timeline。UI 动画以 CanvasGroup、RectTransform 为主，不默认新增外部补间库。

UI 的 Overlay Canvas 会绘制在摄像机画面上，因此应提前统一特效方案。建议首版采用镜头中的背景召唤阵 + Overlay 内的卡面与 Image 动效；需要绕角色运动的真实粒子时，在独立试验场景验证 Camera Canvas 或 RenderTexture 路线后再集成。[Unity 2022.3 Canvas 文档](https://docs.unity3d.com/2022.3/Documentation/Manual/class-Canvas.html)

### 3.2 配置与运行状态

角色、池子、规则、演出引用使用 ScriptableObject。资源、收藏、保底、事件、待展示结果使用独立运行状态与本地 JSON 存档。ScriptableObject 适合静态资源配置；部署后的运行进度另行持久化。[Unity 2022.3 ScriptableObject 文档](https://docs.unity3d.com/2022.3/Documentation/Manual/class-ScriptableObject.html)

核心抽卡计算使用普通 C#，不依赖场景、动画或 MonoBehaviour。便于无动画批量模拟、控制随机源和边界测试。运行时用 `Application.persistentDataPath` 保存完整状态，不把正式收藏放在项目 Assets 或 PlayerPrefs 的零散键中。

### 3.3 AI 可操作性

程序 agent 提供明确的 Editor 菜单工具，用于创建基础配置、受管理的测试场景和 Prefab、检查资源缺失、执行测试和构建。搭建工具应可重跑，并避免清空人工或其他 agent 已完成的对象。

若本轮无法运行 Editor，只交付待验证的代码与运行步骤，状态保持待验收。不能将“生成了 C#”等同于“Unity 中已经可玩”。

## 4. 总指挥与三个角色

| 角色 | 负责 | 交付 | 边界 |
|---|---|---|---|
| 总指挥 | 范围、规则补充、接口冻结、调度、集成、验收 | 任务板、共享契约、主场景、验收记录 | 统一共享文件和构建设置 |
| 美术 agent | 角色设计、本地 ComfyUI、抠图修复、统一风格 | 源图、分层 PNG、缩略图、工作流、生成记录 | 不制作概率逻辑和 UI 文本 |
| 程序 agent | 抽卡、事件、存档、收藏、演出控制、工具 | C#、配置、测试、特效/演出 Prefab、构建入口 | UI 页面由 UI agent 实现，主场景按指挥安排集成 |
| UI agent | 布局、可交互页面、样式、绑定、适配 | Prefab、UI 脚本、mock 场景、截图、交接单 | 不自行扣资源、随机抽卡或写收藏 |

音效首轮由程序 agent 使用原创合成占位音效验证节奏，记录音量和触发点；后续可替换有明确来源的素材。文案初稿由 UI agent 按策划基调编写，总指挥核对含义。无需为原型先增加额外常驻角色。

## 5. 按验收闸门施工

以下是阶段顺序，非已完成状态，也不是交付日期承诺。任务按单个可审核交付拆分，通常一轮只推进一个阶段中的一小批。

| 阶段 | 核心交付 | 前置依赖 | 通过标准 |
|---|---|---|---|
| M0 施工基线 | 目录、构建入口、共享模型、占位资源、环境记录 | 模板核对 | Unity 无新增编译错误；能打开独立测试场景；角色 ID 和文件归属一致 |
| M1 两卡体验切片 | SSR001/UR001、单抽、演出、总览、详情、基础收藏与存档 | M0；两卡构图规范 | 完成一次真实规则单抽；调试可分别演示 SSR/UR；返回后继续抽；退出重进仍拥有卡；遮脸问题清零 |
| M2 连续抽卡 | 12 角色、四档演出、十连、保底、赠礼、跳过、补充、存档恢复 | M1 验收；赠礼冲突规则冻结 | 单抽与十连计数一致；跳过结果不变；断点恢复不重复扣费；基础概率/保底测试通过 |
| M3 题材特色 | 4 共鸣、两条玄学、桌面展示、群聊、公告、完整图鉴 | M2 | 共鸣持续显示；玄学条件/消耗准确；两次点击内首次召唤；桌面内容可忽略 |
| M4 试玩与构建 | Windows 构建、性能记录、15 分钟观察、调整 | M3 | 核心流程无阻断；留存数据可靠；有实际体验记录和剩余问题列表 |

M1 只有两张正式立绘，但先建立全部 12 个角色 ID 的最小配置，另外十名用明确的开发占位图，单抽即可使用基础 70/24/5/1 权重。SSR/UR 强制演示走独立调试通道。完整美术、十连、保底、赠礼要到 M2 才按 V0.1 完整范围验收；占位图不算正式美术交付。

### M0

程序核对 Editor 路径、包导入、构建平台，提供工程初始化工具和共享模型。总指挥冻结接口和文件归属，建议完成本地 Git 基线（排除 Library、Temp、Logs、生成缓存与模型大文件）。UI 准备三页灰盒，美术核对 ComfyUI。

### M1

UI 先用占位图完成召唤/总览/详情。用户已选择先看风格样张：美术先用同一 SSR001 输出三种风格各一张，控制相同构图和角色设定；用户选型后用 UR001 验证一致性，再修复、分层这两张正式图。程序用同一数据契约打通单抽、保存、揭晓和详情，并做两档高级演出。

总指挥将正式图放入实际页面，检查脸部、信息遮挡、透明边缘、动效层级、音画同步与跳过。两卡未通过就修这两卡，不放行其余十名角色的批量生产。

### M2

美术按冻结风格补十张角色图。程序补三档保底、十连顺序计算、新手赠礼、免费资源、完整收藏与存档恢复。UI 补四档提示、概率说明、十连操作和图鉴。

### M3

程序补事件与版本状态，UI 补桌面/聊天/公告/展示卡和版本切换。美术只补必要主题纹样与共鸣装饰；共鸣复用立绘，不新增四套服装。

### M4

总指挥记录首次主动跳过时点、主动欣赏的卡、是否识别高级预兆、记住的出货瞬间。AI 可检查可读性与流程，但“玩家愿不愿意再抽”必须由实际试玩来验证。

## 6. 验收方法

### 正确性

由程序 agent 提供固定随机源与文件故障注入：10/30/100 的临界点、多个保底同触发、赠礼和事件例外、同一十连重复角色的 NEW、保存失败回滚、重启恢复、重复点击与跳过。详细用例见共享契约。

基础概率在关闭保底/赠礼/事件的独立模拟中验证；真实连续抽卡另外统计包含保底后的实际频率。不能直接用完整流程统计要求结果恰好 70/24/5/1。

### 视觉与体验

1920×1080 与 1280×720 检查六页；额外验证 16:10 窗口无按钮截断。每个页面录截图，高级演出提供短视频或实际运行回放。检查角色脸部不被 UI/特效遮挡，普通卡短，高级卡节奏不同，跳过后总览保留全部标识。

初步性能目标为 Windows 实机 1080p、60 FPS；这是待测目标，不是当前保证。M0 记录测试机器，M4 用构建版 Profiler/实机观测加载峰值、透明叠层、十连内存和反复切页。根据实测调整，不预先承诺未测硬件表现。

## 7. 每轮调度与交接

总指挥领取任务 → 核对依赖 → 指定角色及写入范围 → 收到交付 → 静态/运行检查 → 集成 → 更新任务板 → 下一轮。

每个任务单包含：`ID / 目标 / 输入 / 可写范围 / 不包含内容 / 接口依赖 / 交付文件 / 验收步骤`。交接格式在各 agent 提示词中一致。

可并行的内容：已冻结接口下的 UI mock、两卡生成、纯 C# 规则；必须串行的内容：接口改版、共同场景写入、跨文件集成、正式资产批准与批量生产。多个 agent 在同一 Unity 工程写文件时，不同时运行两个 Editor 或同时保存主场景。

## 8. 待定项与默认建议

| 决策 | 当前建议 | 处理时机 |
|---|---|---|
| 画风 | 用户已选择“先由美术 agent 提供风格样张再决定” | A01 同角色三种风格对比后选型，随后两卡验收 |
| 角色 | 先用 SSR001 雾璃、UR001 烬星作为试制设定 | 名称/题材是建议，原案未规定 |
| ComfyUI 模型/显存 | 先核对已装模型，优先现有可运行组合 | A00；暂不写死模型名/节点/采样参数 |
| 共鸣名单 | R001、SR001、SSR001、UR001 | M0 配置冻结 |
| 生日对象 | SSR001，可与主页倾向同次触发 | M3 前冻结；不依赖现实日期或限时领取 |
| 新手赠礼与 UR 保底冲突 | UR 保底优先，赠礼碰撞时前移至同批第九格 | M2 开发前冻结，见共享契约；原策划案未覆盖 |
| 目标硬件 | 当前开发机器、Windows 鼠标操作 | M0 记录，M4 测量 |
| 音效 | 先原创合成占位，再替换必要音效 | M1 验证节奏 |

默认建议仅服务于开工；用户的新指令直接更新相应文档和任务，不需要对每项常规可逆选择重复确认。
