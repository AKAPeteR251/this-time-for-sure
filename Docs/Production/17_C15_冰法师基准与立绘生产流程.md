## 2. 冰法师的视觉基准

- 清晰细线稿、大块赛璐璐阴影与局部柔和渐变；肤色干净，眼睛与表情优先，服装结构和饰物可读。
- 银白长发、冰蓝眼睛、带雪晶的白蓝宽檐尖帽、雪花法杖、露肩收腰开衩白蓝裙；当前图片已有深色过膝丝袜，配黑色短靴，不能把丝袜误记为尚未加入或把腿部统称长靴。
- 从容带笑、轻悬浮屈膝姿态，发丝与裙摆形成流动轮廓。其它人继承画法、精细度与角色魅力，分别设计姿态/服装/道具，不复制她的帽、屈膝姿势或脸。
- 人物、背景、稀有度框、姓名、NEW、元素大光效分开。人物图保留衣物/饰物的正常高光；大光环、散落粒子、地面和烘焙阴影不混入人物层。
- 当前冰法师已验收，继续使用。后续角色要求帽尖、发梢、裙摆、鞋与武器完整，四周目标留5%—8%透明余量；按实际可见轮廓检查，不因为提示词写了padding便认定做到。

## 3. 本地生成步骤与参数起点

### 第一步：每人一张人设卡

从16读取稳定ID、成年年龄、发色/眼睛、反差性格、职业武器、六类元素之一、主色、丝袜颜色/材质、露肤/镂空位置、姿态与表情。先米洛，后赛蕾娜。一人一套已确认造型，首批不做换装/多姿势/Live2D。

把冰法师原图作为目视比较基准。旧本地文生图图没有图片风格条件输入；不能声称上传冰法师就自动获得参考控制，也不凭空加IP-Adapter/ControlNet节点或新模型。

### 第二步：本地生成最多三张候选

复用 [A02冰法师API图](../../ArtSource/Workflows/A02_RPG_01_ice_mage_api.json) / [UI图](../../ArtSource/Workflows/A02_RPG_01_ice_mage_ui.json) 的已跑通链，另存角色新版本，改角色提示词、seed、输出前缀与单色背景。

| 项目 | 起点：沿已记录本地链 |
|---|---|
| 主模型 | anima_turboV11.safetensors |
| 编码器 / VAE | anima_baseV10_txt.safetensors / qwenImage_qwenImageVAE.safetensors |
| LoRA顺序与model/clip强度 | anima/Flatline 0.6/0.6 → anima/chen-bin_v4.0 0.6/0.6 → anima/bakav3-000012 0.8/0.8 |
| 采样 | ClownsharKSampler_Beta，dpmpp_2m / sgm_uniform，8 steps，CFG 1，denoise 1，eta 0.5 |
| 模型patch | AnimaLayerReplayPatcher的replay/spectrum均关闭 |
| 候选 | 768×1152，batch_size 1；逐张运行，先改seed选构图 |
| 解码 | VAEDecodeTiled，tile_size 512 / overlap 64 |

历史模型哈希见 [A01_B_model_hashes.json](../../ArtSource/Metadata/A01_B_model_hashes.json)。执行前核对实际模型/节点及服务，不因旧记录存在便宣称当前可运行。

候选用纯中灰/灰青色背景，无场景/地面/投影/大粒子，利于后续分离。不能在该RGB工作流里写“transparent background”便把输出当RGBA。也不先生成完整UI截图再从中取每个人，以免角色裁切、造型漂移并增加步骤。

先比较脸部/线稿/丝袜材质/职业轮廓与冰法师是否同系列，再选一张继续。普通稀有度同样保持人物质量。每张保存实际正负提示词、seed、API/UI图、prompt_id、history及源PNG。

### 第三步：重建正式母版，再修结构

选中候选后，参考已成功运行的 [A01_B_SSR_master_v002_api.json](../../ArtSource/Workflows/A01_B_SSR_master_v002_api.json) / [UI图](../../ArtSource/Workflows/A01_B_SSR_master_v002_ui.json)，另存新角色图生图工作流。该历史图用于旧角色，必须替换LoadImage输入、角色提示词、seed及输出路径，不能直接运行旧批量脚本覆盖SSR001文件。

图像链：LoadImage（本角色选中候选） → ImageScale（1024×1536，等比、crop disabled） → VAEEncodeTiled → KSampler → VAEDecodeTiled → SaveImage。

历史可执行起点：KSampler使用euler / simple、12 steps、CFG 1、denoise 0.3，编码/解码tile 512 / overlap 64，原模型与LoRA链不变。历史1024×1536运行见 [A01_B_SSR_master_v002_run.json](../../ArtSource/Metadata/A01_B_SSR_master_v002_run.json)。这证明旧图生图链曾完成，不等于新角色已经保持身份或通过验收。

重建后再核对脸/发饰/衣装/武器与候选一致性。单纯ImageScale/Lanczos放大不算新增正式细节；需要实际生成后的线条/纹理质量和结构检查。发现手、握持、丝袜边界、服装连接或鞋尖问题，先修改本张；掩码局部重绘只使用实际已验证的节点/模型，不能把现有整图图生图称为局部修复。未保住造型时降低重绘强度或另选候选，不带缺陷进入批量。

### 第四步：透明处理与边缘精修

本地起点为已有SAM vit_b轮廓分割。权重本轮确认为存在：E:/ComfyUI-aki-v3/ComfyUI-aki-v3/ComfyUI/models/sams/sam_vit_b_01ec64.pth。既有 [SAM脚本](../../ArtSource/Characters/UR001/RPG/a05_sam_extract.py) / [分部修正脚本](../../ArtSource/Characters/UR001/RPG/a05_sam_refine.py) 可供执行agent改为本角色独立流程参考，不能复制旧人物的点/框坐标。

SAM历史运行能分割轮廓，但火战士的细发丝/暗衣边缘仍未获正式通过。它是待验证的透明步骤，不能单靠分割分数作为验收。

人物身体、头发、披风、丝袜、武器分别检查，必要时分部选点/框并合并掩码。不能只保留最大连通块而丢掉独立飘带/武器装饰，也不能沿纯背景颜色阈值把白发/白衣或深色丝袜误擦掉。合并掩码后再修发丝与柔边，衣物镂空处应透背景，丝袜覆盖腿部的区域保持腿与丝袜的绘制内容。

生成和SAM处理串行执行，沿现有6GiB GPU记录控制显存。RMBG/rembg/SAM2等节点注册不代表其权重与输出质量已验证，不作为开工前置，不自动下载新模型。

如果后续任务明确采用内置图像生成路线，可复用冰法师真实验证的“已确认造型参考 → 忠实重建透明人物”方式，工具设置transparent_background=true，并保存实际工具/参考图/提示词与原始输出。它属于另一种实际来源，不伪装为本地ComfyUI出图；本轮不自动切换生成工具。

### 第五步：导出与展示验收

整人物画布统一1024×1536、RGBA，维持姿态与透明余量；不紧裁轮廓再拉伸回2:3。对黑底、白底、中灰底各检查一遍发丝/丝袜/镂空/衣摆/武器边缘，再检查100%脸和手、缩小头像。

输出256×384全身缩略图、256×256脸部头像（交付规格建议），并逐角色记录脸部中心/裁切框。脸部UV约定为左下原点：(cx/width, 1-cy/height)，原始像素坐标为左上原点。当前冰法师配置faceUv=(0.5,0.8)只适用现有图，不能复制给所有角色。

美术先交同背景的冰法师/新角色对照与黑白灰底QA；程序/UI再将同一角色接到逐张大到小特写、头像总览和详情中实际运行验收。美术合成图不是Unity截图，不能替代实际运行。保留P32已验收结算布局，不通过新素材任务改界面。

## 6. 学习点与调参

Unity概念：RGBA与假透明的区别、Sprite整画布与Preserve Aspect、Alpha Is Transparency、脸部UV和头像裁切、人物/背景/UI/大光效分离、.meta/GUID稳定引用。

调参顺序：先脸/表情和职业轮廓 → 服装/丝袜/镂空 → 姿态/武器安全边距 → 正式尺寸图生图强度 → 掩码与发丝边缘 → 头像裁切/脸部焦点。采样参数先保持已跑通起点，一次改一个主要变量；种子只记录复现条件，不当成跨角色画风保证。
